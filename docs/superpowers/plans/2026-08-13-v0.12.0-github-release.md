# v0.12.0 GitHub Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish GitHub Release `v0.12.0` from the exact validated `main` state after converting its changelog entry from an unpublished package state to tagged history.

**Architecture:** Treat the changelog transition as a tested release-ledger state change on a dedicated branch. Merge that preparation through a reviewed PR, then create one annotated tag on the exact merge commit and let the existing tag-triggered Release workflow validate and create the GitHub Release.

**Tech Stack:** Markdown, Python 3 standard-library validators and mutation tests, Git, GitHub CLI, GitHub Actions, Debian WSL, Node.js 24.17.0.

## Global Constraints

- Keep `nori.json`, `.nori-version`, `README.md`, and `docs.md` at `0.12.0`.
- Publish `0.12.0` with effective date `2026-08-13`.
- Preserve all 18 existing `0.12.0` release bullets without rewriting them.
- Keep `0.11.1`, `0.11.0`, `0.9.1`, `0.9.0`, and `0.8.0` unpublished.
- Do not manually create the GitHub Release or bypass the tag-triggered Release workflow.
- Do not force, move, replace, or delete an existing tag.
- Do not upload this package or its components to the Nori registry.
- Use command-local `safe.directory` for authorized host Git operations; do not change operator-global Git configuration.
